# 036 · What Is an AI Software Factory?

_Location: Giza Pyramids. Duration: ~45 seconds._

## Script

4,500 years ago, the Egyptians built these pyramids.

Thousands of workers, each with a specific job, following a plan.

Now imagine one person trying to do everything.

Sounds ridiculous, right?

Well, that's exactly what we're doing with AI.

Instead of one giant agent, an AI software factory uses smaller agents, each with one job.

One writes the spec, one plans, one builds, one tests, one reviews, and one deploys.

And just like building a pyramid, humans still check the important stages.

They approve plans, review changes, and control releases.

Because the goal isn't more code.

It's better software, every time.

Jon Shanks explains the approach. Link below.

## Notes
- The blog's nine stages: Intent → Spec → Design → Plan → Build → Test → **Review (gate)** → **Release (gate)** → Operate. The script only names six to keep the pace. The full nine can sit on screen as the layers of the pyramid.
- People stay in the loop all the way along: a person accepts the spec, signs off the design, accepts the plan before anything is built, and controls what gets merged. At the release gate, low-risk changes ship themselves and anything risky waits for a named person.
- "Not a lot of coding agents": the blog's distinction is agents doing *discrete* tasks that hand over to each other, like stages on a production line.
- The payoff in the blog: smaller teams with the factory carrying the repeatable work, so "a team of three can now carry a lot of the work", and you can create more product teams from the same people.
- Takeaway to use today, factory or not: give each agent one job and put a human approval where the work becomes hard to undo.
- The Great Pyramid dates to around 2560 BC, so "4,500 years ago" holds up.
